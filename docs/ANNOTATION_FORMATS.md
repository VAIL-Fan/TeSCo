# EgoExo4D Annotation Formats Reference

This document explains the different annotation files used in LM-EEC and how they relate to each other.

---

## 1. Per-Video `annotation.json`

**Location:** `data/EgoExo4D/{split}/{take_id}/annotation.json`

**Structure:**
```json
{
  "masks": {
    "object_name": {
      "aria01_214-1": { "0": <RLE>, "30": <RLE>, "60": ... },
      "cam04": { "300": <RLE>, "330": <RLE>, ... }
    }
  },
  "subsample_idx": [0, 30, 60, ...]
}
```

**Used by:**
- **Inference** (`tools/correspondence_inference.py`): Reads `masks[object][cam][frame]` to get ego GT masks as input prompts. Frame keys are strings (e.g. `"0"`, `"30"`).
- **Training** (`training/dataset/`): Loads segments for sampled frames via `JSONSegmentLoader`.

**Notes:**
- **Image files on disk** are sampled at 1 frame per 30 frames. All cameras share the same indices: 0, 30, 60, 90, 120, … (e.g. `aria01_214-1/0.jpg`, `gp01/0.jpg`, `gp02/0.jpg` refer to the same moment).
- **Annotation keys** differ per camera: ego may have masks at 0,30,60,90,… (dense) while exo has 0,300,600,… (sparse). Only some frames are annotated per view.
- Inference uses `np.intersect1d(ego_annotated_frames, exo_disk_frames)` to find frames that have both ego masks and exo images.
- If a requested frame is missing from the annotation, `load_masks_from_dir_by_json` raises `KeyError` (no fallback to avoid corrupting inference).

## 2. Take-Level `relations_{split}.json`

**Location:** `data/EgoExo4D/annotations/relations_val.json`, `relations_test.json`

**Structure:**
```json
{
  "ds": "...",
  "annotations": {
    "take_id": {
      "scenario": "...",
      "take_name": "...",
      "object_names": [...],
      "object_masks": {
        "object_name": {
          "aria01_214-1": {
            "annotation": { "5130": <RLE>, "5160": <RLE>, ... },
            "annotation_metadata": {...},
            "annotation_fps": 1,
            "annotated_frames": [...]
          },
          "cam04": { ... }
        }
      }
    }
  }
}
```

**Used by:**
- **merge_pred.py**: Determines which objects and camera pairs to evaluate. Iterates over `annotations[take_id]["object_masks"]` to know which objects have both ego and exo annotations.
- Defines the canonical list of takes and object/cam pairs for evaluation.

**Notes:**
- Contains 267 val takes; only 201 have corresponding video folders in `val/`.
- Camera names (e.g. `aria01_214-1`, `cam04`) match folder names under each take.
- Pred output folders use `ego__exo` (e.g. `aria01_214-1__cam04`).

## 3. Evaluation `gt_results/*.json`

**Location:** `data/EgoExo4D/gt_results/egoexo_val_gt.json`, `egoexo_test_gt.json`

**Structure:**
```json
{
  "ego-exo": {
    "version": "xx",
    "challenge": "xx",
    "results": {
      "take_id": {
        "masks": {
          "object_name": {
            "aria01_214-1_gp02": {
              "0": { "pred_mask": <RLE>, "confidence": 0|1 },
              "30": { ... }
            }
          }
        },
        "subsample_idx": [0, 30, 60, ...]
      }
    }
  }
}
```

**Used by:**
- **compute_metrics.py**: Compares predictions vs ground truth. Expects `ego-exo` or `exo-ego` top-level key.
- GT format uses `pred_mask` and `confidence` keys per frame (same as prediction format for consistency).

**Notes:**
- Camera keys use underscore: `aria01_214-1_gp02` (merge_results converts `__` → `_` from pred format).
- Frame keys are strings.
- Pre-generated by the EgoExo4D benchmark; not created by LM-EEC scripts.

## Data Flow Summary

```
Per-video annotation.json     →  Inference (input masks)
        ↓
Inference output               →  pred/take_id/ego__exo/object/frame.json
        ↓
relations_*.json               →  merge_pred (which objects/cams to merge)
        ↓
merge_pred output              →  pred/take_id/annotations.json
        ↓
merge_results                 →  egoexo_val_results.json (pred format)
        ↓
compute_metrics               →  Compare pred vs gt_results/egoexo_val_gt.json
```

## Common Errors

| Error | Cause |
|-------|-------|
| `KeyError: '30'` or `'300'` | Requested frame not in `annotation.json` for that object/cam. Check frame intersection logic. |
| `KeyError: 'ego-exo'` | GT or pred JSON uses `exo-ego` instead. Fixed via `get_task_data()` in compute_metrics. |
| `KeyError` in merge_pred | Take not in relations, or object/cam structure mismatch. |
